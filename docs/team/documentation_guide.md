# Team Documentation Guide

## Where work goes

- Individual notebooks go in `notebooks/<your-name>/`.
- Final notebooks and generated outputs go in `notebooks/final-deliverables/September/` under the appropriate gate.
- Reports and review documentation go in `docs/team/september/` under the appropriate gate.

## Before marking an issue Done

1. Complete the work described in the issue.
2. Run the final notebook from a fresh kernel and check the outputs.
3. Complete the issue checklist. Leave unfinished requirements unchecked.
4. Add a short artifact report using the shared template.
5. Link the final notebook, generated evidence, and report in an issue comment.
6. Record any anomalies, limitations, and handling decisions.
7. Have another teammate review the work when independent verification is required.
8. Record the reviewer's name and any unresolved feedback.

Do not close an issue until its required checks and documentation are complete.

## Updating final artifacts

Generate calculated values directly from the documented source and configuration. Do not manually edit calculated outputs.

Make changes on your branch and submit a PR for review. If an artifact changes after approval, rerun the relevant checks and update its documentation.

## Issue comments

Every completed issue should have a comment explaining what was done, where the final artifacts are located, the main results, and who reviewed them.

The report contains the detailed evidence. The issue comment can remain short.
